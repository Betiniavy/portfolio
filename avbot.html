Case Study

Avbot

A calm, non-clinical emotional support chatbot designed to guide users through structured self-kindness conversations.

Role: Frontend Developer (UX & Product focus) Stack: HTML, CSS, JavaScript, JSON dialogue model Focus: Conversation state, accessibility, emotional safety
View Demo GitHub ↗

Project Overview

Avbot is a lightweight chatbot prototype built to support users in moments of stress or self-criticism. Instead of open-ended AI responses, the experience uses a controlled dialogue flow to keep interactions predictable, calm, and emotionally appropriate.

This project demonstrates product thinking and frontend implementation, with particular focus on conversation state management, readability, and safe interaction design.

The Problem

Many wellbeing tools feel either too clinical or too generic, and users often abandon experiences that require high effort when they’re already overwhelmed.

The goal was to create a low-friction, non-clinical conversational experience that helps users pause, self-regulate, and practice self-kindness—without positioning the product as therapy or crisis support.

Goals & Success Criteria

  • Deliver a calm, emotionally safe tone with clear boundaries
  • Keep interaction short and lightweight (2–3 minutes to complete)
  • Make the flow predictable, with user control at each step
  • Build a maintainable frontend architecture using a structured dialogue model
  • Ensure strong readability and accessibility across devices

Design Snapshot

The interface is intentionally minimal. The conversation is structured as a decision tree, where each step presents a small, clear set of options.

Process

Research & Framing

Reviewed existing conversational support tools and defined product boundaries to keep the experience non-clinical, supportive, and easy to engage with.

Conversation Design

Mapped a structured dialogue tree to maintain predictable tone and safe responses. Designed short prompts to reduce cognitive load and encourage follow-through.

Frontend Build

Implemented a responsive UI and a JSON-driven conversation model, separating rendering logic from conversation state for maintainability.

Technical Implementation

  • Built with semantic HTML, modular CSS, and vanilla JavaScript
  • Dialogue stored in a JSON-like structure (nodes, options, transitions)
  • State handled via explicit node IDs to avoid unpredictable responses
  • UI rendering kept separate from flow logic for clean iteration
  • Responsive layout designed for mobile-first readability

This architecture keeps the product lightweight and easy to extend while maintaining predictable user experience and emotionally safe boundaries.

Challenges & Solutions

Managing conversational state cleanly
A key challenge was ensuring transitions never broke flow. I used an explicit node-based model (IDs + transitions) so every user action maps to a known next state.

Balancing empathy with predictable structure
Free-form outputs were avoided in favour of controlled paths. This kept tone consistent and reduced the risk of unhelpful or unsafe responses.

Reducing cognitive load
Messages were kept short and options limited, improving clarity and preventing decision fatigue.

Outcome

The result is a working chatbot prototype that demonstrates safe conversational UX, structured state handling, and a calm interface optimised for readability. The dialogue model is extendable, making it practical to add new modules without rewriting the UI.

Reflection & Next Steps

  • Add more conversation modules (e.g., confidence, burnout, social anxiety)
  • Introduce an optional journaling step (private, user-controlled)
  • Improve evaluation with structured usability testing
  • Add accessibility enhancements (reduced motion, keyboard-first interactions)
